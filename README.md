## About

The purpose of this project is to explore the predicability of atmospheric trace substance concentrations from the underlying meteorological and spatial signature captured in a measurement of atmospheric composition.

This project/model are very much in the development stage. Results are preliminary.

The PASTEL model uses meteorological variables calculated at along backwards trajectories generated by the NOAA HYSPLIT model as inputs to make predictions about atmospheric trace substance concentrations
  using a hybrid global and regional ensemble system utalizing both random forest regression and linear regression.

## Getting Started

Clone the repository and look at the Zenodo link to get the final cleaned csv used for the main "code/v0_1_5_PASTEL.ipynb" file. 

This is a priliminary file so it will be necessary to change directory paths within the PASTEL file itself.

Be sure to look at 'Prerequisites' section for necessary packages. Or use the provided environment file

### Prerequisites

The provided 'pastel_env.yml' file is the environment with the packages currently required to run the main pvocal_env file. 

To install the environment file run this line in an anaconda prompt window:

  conda env create -f pastel_env.yml

There is currently a dependancy issue with this environment and the version of matplotlib basemap used within PySPLIT. A new environment will need to be created to run any code for PySPLIT trajectory generation.

### Installation

Make sure to use the provided environment file and find the data in the Zenodo link.

## Features

It can predict 6 target compounds: DMS, Ethane, Ozone, Carbon Monoxide, Methane, and Methyl Bromide being what I focused on grabbing from the various airborne campaings. Within the underlying airborne campaigns that went into making the input dataset there is room for many more to be incorporated.

## Contributing

Main contributions include making the model compatible with all VOCs from each airborne campaign (joining all inconsistant nams into one input dataset) and adapting code so that this process is more streamlined. Additionlly, I could use some help transforming absolute paths to relative paths in a way that is system/os agnostic.

Turning this code it into a package so other folks can begin to use the model in their workflows is probably the biggest thing that needs to be done. This will probably mean a transition from notebook files to .py/object oriented scripts.

Misc projects:
- Given the findings in the paper published with this repository, PASTEL could be seen as an interpolation tool (but a very good one), so work exists to transition PASTEL to a DANN architecture, one that may have an easier time with spatial extrapolation. Although the DANN architecture also still has some quirks: can only handle maximizing binary source/target classifications. If this could be expanded to just a general classifier, we could use KGCCL regions to look for domain invarient patterns in meterology/space, and then try to expand generalization/spatial extrapolation capabilities to places with less/no data. This would be the ultimate goal.
- Additionally there exists a package for Utility Based Regression in R here: https://github.com/paobranco/UBL I believe that implementing this for python and as a part of this project would be benifical for more accurate predictions while using the SMOGN algorithm.
